Keep an experiment’s recordings, models, results, CAD, scenes and runtime snapshots together in data/<study>/. The RS05 archive illustrates this layout. The old root results/, models/, assets/ and environments/ locations are also ignored to prevent accidental reintroduction. Documentation retains only images it actually uses; figure prompts, reference renders and intermediate outputs belong to the experiment archive.

The offline example is self-contained. Its data, frozen model and reference predictions are deliberate small fixtures. Copy that directory to use it elsewhere. New fits and output files must go to a new path under data/<study>/ or outputs/; never overwrite a frozen fixture.

Before committing#

Stage named source paths, then inspect and check the staged tree:

git diff --cached --stat
python3 scripts/check_repository.py
git diff --cached --check

The checker inspects the Git index, including forced additions and previously tracked ignored files. GitHub CI runs it alongside lint, tests and the offline example from a fresh checkout. The checker permits source extensions in designated directories and explicitly lists example records, regression artifacts and documentation images. It also limits each blob to 5 MiB and the source/fixture total to 20 MiB (the BAM submodule has its own history).

Adding a new intentional fixture requires reviewing and updating the allowlist in scripts/check_repository.py along with its consumer and documentation. Do not expand it for ordinary experiment outputs or use it to upload local archives.

Adding an ignore rule does not untrack existing files or remove their history. If an experiment file was accidentally staged, unstage it and keep the local copy. History cleanup requires a separate, deliberate rewrite and a verified backup outside the repository.
