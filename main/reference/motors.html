Supported motors#

MotorFit records RobStride and Damiao motors through Linux SocketCAN. Choose a profile matching both the motor model and its firmware protocol, then use it in a bench setup.

Family

Supported protocol

Starting setup

RobStride

Manufacturer private protocol over extended CAN

configs/setups/rs05_pendulum.toml

Damiao

MIT control over standard CAN

configs/setups/dm4310_pendulum.toml

Both drivers support feedback reading, register inspection, software-zero capture and trajectory recording. Their recordings use the same fitting workflow.

RobStride profiles#

The configs/motors/robstride/ directory contains:

Models

Profile files

RS00, RS01, RS02

rs00.toml, rs01.toml, rs02.toml

RS03, RS04

rs03.toml, rs04.toml

RS05, RS06

rs05.toml, rs06.toml

For example, an RS06 setup uses ../motors/robstride/rs06.toml when the setup is under configs/local/. Each model has its own position, velocity, torque and gain encoding ranges. Do not substitute the RS05 profile merely because the wire format is shared.

The RobStride driver targets the private extended-CAN protocol. Alternative CANopen or MIT firmware layouts require a different adapter.

4340_v20 is the repository’s profile name for DM4340X. It is distinct from the standard DM4340 profile. Before enabling, the driver checks the device’s PMAX, VMAX and TMAX against the selected profile.

Serial bridges and the DM_Device SDK transport are not implemented. Use a SocketCAN-compatible adapter.

What a profile contains#

A profile stores the model name, family and command-encoding ranges in SI units. These ranges describe the protocol; they are not identified friction, inertia or rated continuous-torque values. Physical parameters come from an experiment and are saved separately in model.json.

List the installed profiles and validation coverage with:

uv run --no-sync motorfit motors
uv run --no-sync motorfit motors --json

Validation coverage#

RS05 has recorded hardware evidence in the reference study. The other RobStride profiles and all Damiao profiles require commissioning on the actual unit. Software tests check protocol encoding, response matching, startup checks, error cleanup and the offline fitting path; they do not establish accuracy on every motor listed above.

Continue with Setup to configure a mounted device. For wire formats, register behavior and manufacturer sources, see Protocols.
